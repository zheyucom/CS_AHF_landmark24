# 本院 DHF eMAR 目标药物提取规范 V2

版本：2026-09-24
状态：`approved_for_data_request_pending_actual_emar_delivery`

本规范用于向信息科申请目标药物的执行级记录。它只扩大 eMAR 提取覆盖，不改变已冻结的研究一主队列、研究二/三结局或 A+B+C 操作性表型。

## 1. 提取范围

本次提取共覆盖 2,150 个 ICU episode：

| 层级 | 人数 | 用途 | 是否直接进入主分析 |
|---|---:|---|---|
| `A+B+C` 主队列 | 773 | 研究一主队列及短期执行结局核对 | 是，按既有方案 |
| `A+B` 缺 C | 340 | C 域漏检/治疗证据敏感性审计 | 否，敏感性层 |
| `B+C` 缺 A | 766 | 心衰锚点缺失边界层 | 否，暂存待审核 |
| `A+C` 缺 B | 271 | 失代偿证据缺失边界层 | 否，暂存待审核 |
| **合计** | **2,150** | 目标药物 eMAR 资料库 | 不能据此扩大主队列 |

这 2,150 人来自当前 8,385 名床旁心超成人 ICU 候选中的四个高信息层。仅提取目标药物，不申请全量住院 eMAR。

## 2. 时间和连接键

每个 episode 提取 `[T0,T60)`：

- `T0`：index ICU 入科；
- `T12=T0+12小时`；
- `T60=T0+60小时`。

必须使用 `patient_id + visit_id + episode_id` 连接，不能仅用患者 ID。每条记录应能回连到项目时间表中的 T0、T12、T60。

## 3. 药物清单

### 3.1 主执行层：升压药/正性肌力药

原始药名必须保留，规范化字段按以下类别映射：

- 去甲肾上腺素：去甲肾上腺素、重酒石酸去甲肾上腺素、集采/厂家变体；
- 肾上腺素：肾上腺素；匹配时排除去甲肾上腺素、异丙肾上腺素、去氧肾上腺素；
- 血管加压素类：血管加压素、垂体后叶素；
- 去氧肾上腺素；
- 多巴胺；
- 多巴酚丁胺；
- 米力农。

### 3.2 扩展敏感性层

以下本院实际出现的药物必须提取，但先不自动并入主 `target_event`：

- 异丙肾上腺素；
- 左西孟旦；
- 特利加压素。

它们可能用于正性肌力、心率支持、肝肾综合征或消化道出血等不同场景，需结合实际执行时间、途径和临床适应证再判断。

### 3.3 静脉袢利尿剂层

提取：

- 呋塞米针/注射液及集采、厂家、规格变体；
- 托拉塞米针及集采、厂家、规格变体。

仅纳入静脉注射、静脉滴注或明确静脉泵入。口服呋塞米、口服托拉塞米、螺内酯和噻嗪类不属于本次目标层。本院订单核对未发现布美他尼或依他尼酸，不要求额外扩展。

静脉袢利尿剂用于 C 域复核和照护路径描述，不自动构成血流动力学恶化事件。

## 4. 必须提供的字段

### 4.1 连接与时间

`patient_id`、`visit_id`、`episode_id`、`order_id`、`mar_event_id`、`order_time`、`administration_time`、`infusion_start_time`、`infusion_stop_time`、`rate_change_time`。

### 4.2 药物与执行

原始药品名称、规范化通用名、规范化类别、规格、浓度、剂量、剂量单位、输注速率、速率单位、给药途径、给药方式、执行状态、状态代码字典、暂停/拒绝/取消原因、来源表和导出批次。

执行状态至少应能映射为：

`given`、`started`、`rate_changed`、`stopped`、`held`、`refused`、`cancelled`、`partial`、`unknown`。

## 5. 记录解释底线

- `医嘱产生`不能替代实际给药；
- `医嘱停止`不能替代实际停止给药；
- `取药`不能视为给药；
- `术中`不能自动算作 ICU 循环支持升级；
- `静脉注射（泵）`是泵入候选，但仍需 eMAR 执行状态确认；
- 缺少实际执行时间、途径或执行状态时，编码为 `unknown`；
- T12 时已有同类支持但没有可靠速率/剂量变化时，不能推断强化。

## 6. 结局使用边界

### 主执行级候选事件

T12 时无同类有效循环支持，且 T12 后出现明确 `started/given` 的升压药或正性肌力药，或者有可验证的连续输注速率强化，可作为 `target_event` 候选。最终仍需按现有结局合同处理竞争事件、行政终止和 unknown。

### 静脉袢利尿剂

T0–T12 的实际执行记录用于 C 域和治疗路径审计；T12 后的执行记录可做次要照护路径分析，但不自动定义主血流动力学恶化。

### 四个边界层

从 `B+C` 缺 A、`A+C` 缺 B 和 `A+B` 缺 C 中获得的 eMAR 只进入资料库和敏感性审计。即使发现实际用药，也不能自动改写 773 人主队列；如需纳入，必须建立新版本表型并重新进行临床校准。

## 7. 信息科筛选摘要

```text
人群：项目提供的 2,150 个 ICU episode
时间：每个 episode 的 [T0, T60)
药物：主升压/正性肌力层 + 扩展敏感性层 + 静脉袢利尿剂层
必须保留：实际执行时间、执行状态、途径、剂量、浓度、速率、开始/停止/速率变化时间
不需要：全量住院口服药、普通护理执行项、与目标药物无关的医嘱
```

## 8. 接收后的质量门

收到 eMAR 后，先核对：连接键、时间回连、状态代码、药名别名、静脉/口服区分、泵速变化、代理阳性重新分类、unknown 重新分类和首次事件时间。质量门通过前不重跑短期结局。

## 9. 研究设计边界

- 研究一主分析仍为 773 人；
- 340、766、271 三个边界层不自动并入主分析；
- 研究三最终时间外部验证队列冻结后，如出现 2,150 人之外的新 episode，再追加其目标 eMAR；
- eMAR 不用于修改 MIMIC 队列、MIMIC 变量合同或研究一 T0 死亡结局；
- 原始 `DHF_SRR/` 文件保持只读。
