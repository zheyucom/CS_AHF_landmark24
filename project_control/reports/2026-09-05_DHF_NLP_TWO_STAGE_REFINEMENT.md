# DHF 两阶段 NLP 与时间表型优化方案 v1.0

日期：2026-09-05 Asia/Shanghai  
定位：DHF 入组表型验证与院内外部验证准备；不是将自由文本直接作为主模型预测器

## 1. 结论

用户提出的“两阶段”思路可行，而且比单靠 BNP、ICD 或单一影像关键词更接近 DHF 的临床判断：

1. **广度筛查**：用结构化数据建立候选池，包括 HF anchor、NT-proBNP/BNP、呼吸频率、SpO2、氧疗/无创通气/有创通气、利尿剂和血管活性药物等。
2. **精度确认**：在 ICU 入科前可获得的急诊、普通病房、会诊和入院记录中，抽取呼吸困难/端坐呼吸/夜间阵发性呼吸困难、肺部啰音、颈静脉充盈、下肢水肿、肺水肿/容量超负荷、医生对 HF/DHF 的评估，以及 PE、肺炎、ARDS、COPD、ACS 等替代或并存解释。
3. **时间门控**：每条文本概念必须同时保存“事件发生时间”和“文本可用时间”；只有 `availability_time < T0` 的文本才能证明 ICU 前已经存在该临床表现。T0-T12 期间获得的文本可用于截至 T12 的表型，但不能回填为 T0 前诊断。

NLP 可以提高识别的召回率和上下文准确性，但不能把“提到某个词”直接等同于 DHF。DHF 是临床综合征，文本抽取应输出可审计的症状、体征、评估、否定、不确定、历史状态和时间关系，最终由预先冻结的组合规则和人工验证形成 operational phenotype。

## 2. 推荐的证据链

```text
结构化候选池
  -> 文本概念抽取（症状/体征/诊断/治疗/替代解释）
  -> assertion：present / absent / possible / historical / family / hypothetical
  -> temporality：current / prior / future / retrospective / unknown
  -> document availability gate：pre-T0 / T0-T12 / post-T12
  -> patient-level evidence table
  -> DHF candidate / multidomain DHF / echo-supported DHF
```

建议将“呼吸窘迫”拆成多个可解释概念，而不是只设一个变量：

| 证据域 | 例子 | 输出 |
|---|---|---|
| 症状 | dyspnea、orthopnea、PND、呼吸困难、不能平卧 | present/absent/possible + 时间 |
| 体征 | crackles/rales、JVP 增高、外周水肿、发绀 | present/absent/possible + 时间 |
| 肺部证据 | pulmonary edema、vascular congestion、间质水肿、胸腔积液 | CXR/CT 来源 + 结果可用时间 |
| 心脏证据 | LV/RV dysfunction、充盈压升高、瓣膜病、LVEF | Echo 来源 + 结果可用时间 |
| 治疗/管理 | 实际 IV 袢利尿剂、NIV、插管、氧疗、血管活性药物 | 实际发生时间和剂量/强度 |
| 替代解释 | PE、pneumonia、ARDS、COPD、ACS、肾衰 | 并存/替代/未确定 |

## 3. NLP 技术路线

### 阶段 A：可审计规则基线

先用医学词典、同义词、缩写、否定词和不确定词构建 section-aware 规则。保留句子、字符位置、触发词、否定/不确定窗口、文书类型和规则版本。规则覆盖应包括英文 MIMIC 文本和院内中文文本，但两种语言分别维护词典并分别验证。

规则基线需要处理：

- 否定：`no dyspnea`、`denies orthopnea`、无呼吸困难；
- 不确定：`possible edema`、`cannot exclude`、考虑肺水肿；
- 历史：`history of CHF`、既往心衰；
- 家族/假设：`family history`、`if develops dyspnea`；
- 模板复制和计划性描述；
- 诊断与症状的区分：`respiratory distress` 是症状/体征，不自动等于 DHF；
- 替代解释和并存病因：PE、肺炎、ARDS、COPD、ACS、肾衰不应因为共存就机械排除，但必须单独编码。

### 阶段 B：经过标注验证的上下文模型

300 条胸部影像报告不能训练完整的症状 NLP 模型；它们只能验证影像域。若取得院内或 MIMIC 可用的 ICU 前临床笔记，应新增独立的文本标注集，按患者和文书分层抽样，至少标注：概念、断言、时间、证据域和替代解释。

在有足够人工标签后，按以下顺序比较：

1. 词典 + NegEx/ConText 类规则：解释性最强，作为基线；
2. 句子/段落级 ClinicalBERT 或 BioClinicalBERT：适合上下文分类和断言识别；
3. 轻量级医学语言模型或经约束的 LLM：仅作为候选抽取器，必须在锁定测试集上与规则和 BERT 独立比较。

不建议一开始用大语言模型直接从全部病历生成“DHF 是/否”。原因是：临床笔记存在模板复制、回顾性叙述、否定和时间混杂；LLM 可能产生不可重复的解释，且不天然解决文本可用时间。模型必须输出结构化 span、断言、时间和证据，而不是只输出二分类结论。

## 4. 入组表型如何使用文本

文本 NLP 的第一用途是**改善表型确认**，而不是扩充预测器。建议冻结三层：

| 层级 | 组成 | 用途 |
|---|---|---|
| `candidate` | HF anchor + 结构化支持证据 | 全候选宇宙与敏感性 |
| `multidomain_DHF` | HF anchor + 文本/影像/心超任一客观或临床失代偿域 + 时间合规治疗/管理强化 | MIMIC 主开发表型候选 |
| `echo-supported_DHF` | 上述条件 + T12 前可解析且支持异常的心超结果 | 院内严格验证层 |

文本中的“呼吸窘迫”“需要氧疗”“NIV/机械通气”可支持临床失代偿和严重程度，但单独不能证明心源性。氧疗/通气可能由肺炎、PE、ARDS、COPD 或术后因素引起；应与肺部影像、心超、HF 背景和替代解释联合判定。

自由文本**不得**直接作为主模型预测器，除非另行预先规定：文本可用时间、特征编码、训练折内处理、跨医院词汇迁移和锁定测试集验证。否则会同时引入信息泄露、数据集特异性和不可复现风险。

## 5. 标注与验证设计

文本 NLP 至少需要两类标注集：

1. **概念/上下文集**：每条句子或 span 标注 present、absent、possible、historical、hypothetical，以及 current/prior/unknown。
2. **患者级表型集**：盲法判断该患者在 T0 前或 T12 前是否有可接受的临床失代偿证据，并记录依据文书和最小证据片段。

训练、调参和测试按患者分组切分，不能让同一患者的不同文书跨集合。测试集在规则和模型开发完成前锁定。报告 precision、recall、F1、PPV、NPV、敏感性、特异性和 95% CI；患者级表型还应报告与临床裁决的一致性和 inter-rater kappa。

300 条当前胸部影像报告的用途仍是验证 CXR/CT 肺部证据，不能替代上述症状/体征文本标注。第二位标注者必须独立盲法完成 60 条，当前同标注者复制不能作为正式 kappa。

## 6. 时间序列关键规则

- `document_event_time`：症状/体征或医生判断在临床上发生的时间；
- `availability_time`：文书创建、签署或结果可见时间；
- `T0`：ICU 入科时间；
- `T12`：ICU 入科后 12 h。

优先级：结构化事件时间 > 文本明确写出的事件时间（需人工验证） > 文书创建/签署时间（仅作为可用性回退）。出院小结对早期事件的回顾性描述不能默认等价于当时已可用的信息。

这一步对你的研究尤其重要：如果目标是“入 ICU 前已经发生 DHF/急性失代偿”，就使用 `availability_time < T0` 的文本；如果目标是“截至 ICU 早期 T12 可确认 DHF”，可以纳入 `[T0,T12)` 内新出现且可追溯的证据，但研究问题和队列名称必须明确为 `identified by T12`，不能写成 pre-ICU-confirmed。

## 7. 文献依据与借鉴方式

已有方法支持本方案的几个核心原则：

- ARIC Framingham HF phenotype 研究显示，住院 EHR 的结构化数据结合 NLP 可提高 HF 表型识别，但需要多中心验证，不能把单中心规则直接当金标准（PMID: 34127492，doi:10.1136/bmjopen-2020-047356）。
- eMERGE HF phenotype 工作采用可复现的多源 EHR 规则并区分 HFrEF/HFpEF，说明 HF 表型适合采用结构化数据、诊断和文本的组合，而不是单一 BNP（PMID: 26195183，doi:10.1007/s12265-015-9644-2）。
- NegEx 提供了可审计的否定语境处理基础（doi:10.1006/jbin.2001.1029）；ConText/断言识别思想进一步要求处理历史、不确定和假设语境。
- CheXpert 说明放射科报告中的不确定性、否定和专家标注必须单独处理（doi:10.1609/aaai.v33i01.3301590）；本项目因此采用规则筛查后人工复核。
- 临床 NLP 综述提示 HF 研究可从症状、体征、影像、诊断和治疗文本中构建表型，但跨机构词汇、模板和时间语义是主要外部验证风险（PMID: 39699708，doi:10.1007/s10741-024-10472-0）。
- 2025--2026 年 HF/心肺症状研究显示，BERT、弱监督和 LLM 可用于症状抽取或病例识别，但应作为经过人工标注验证的抽取模块，不能绕过表型定义和时间审计（PMID: 40208662、40674251、42206405）。这些较新的研究应作为方法参考，不替代本项目的本地验证。

## 8. 立即执行顺序

1. 先完成当前 300 条 CXR/CT 报告人工复核，形成肺部证据域验证集。
2. 向 MIMIC/院内数据管理员确认是否能提供 ICU 前急诊、入院、会诊、护理和初次病程文本，以及创建/签署/可见时间。
3. 若可获得，抽取结构化文本候选表：一行一个概念事件，包含 `patient/stay/document/span/concept/assertion/temporality/event_time/availability_time/source/rule_version`。
4. 人工标注独立训练/验证/测试集；先验证规则，再决定是否训练 ClinicalBERT/BioClinicalBERT 或受约束 LLM。
5. 在患者级完成 DHF 表型验证和替代解释审计后，重新计算事件数与 EPV，再冻结模型变量。

## 9. 当前决策

你的初步方案保留并优化为：**结构化数据广筛 + 时间门控的上下文 NLP 精筛 + 心超/影像/治疗多域确认**。不建议现在立即训练 BERT 或 LLM；当前最有价值的工作是先确认可用文本范围和时间字段、建立人工金标准、做规则基线和时间序列表。完成这些后再比较 BERT/LLM 是否有增量价值。
