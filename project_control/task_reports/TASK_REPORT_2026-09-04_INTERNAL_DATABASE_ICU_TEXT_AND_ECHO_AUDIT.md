# 任务报告：本院 ICU 文本、时间与心超能力复核

日期：2026-09-04  
任务：复核“我院数据库”样例能否支持 ICU 时间、ICU 结局、实际用药和心超证据提取，并确定下一步信息科确认项。

## 结论

样例中确实存在 ICU 患者相关记录，但样例的原始筛选条件是“脑梗死+出院小结+65岁”，不是本研究的 ICU-DHF 队列。因此，样例只能证明数据源和抽取方法可行，不能提供正式队列人数或心超缺失率。

本院研究仍按以下主线推进：先提取全部连续成年 ICU 候选者，再按冻结的 `T0/T12` 和 DHF 多域规则筛选；院内严格验证层要求 T12 前实际完成且结果可用、支持结构/功能异常的心超，同时具备肺充血/临床失代偿及治疗强化证据。T0 时不要求已经完成 DHF 诊断。

## 样例已经证明的能力

### 1. ICU 流转和文本时间

`rdr_medrecord_list` 中存在：

- “入ICU记录”：739 条记录、711 个就诊；
- “出ICU记录/ICU转病房记录”：1,424 条记录、746 个就诊；
- “病房转ICU记录”“再入ICU记录”等文书；
- ICU 科室文书共 13,818 条记录、1,326 个就诊。

部分正文包含明确的“入ICU时间”“出ICU日期”。因此，急诊/病房到 ICU 的临床过程、入出 ICU 文本时间和部分出科状态可以做规则抽取与人工核查。

主分析的时间来源必须固定为：

1. 结构化 ICU stay 的 `intime/outtime`；
2. 入/出 ICU 文书正文中的明确时间；
3. 文书创建时间，仅作为最后回退，并标记 `time_source=text_fallback`。

文书创建时间、正文记录时间、报告时间可能不一致，三者必须保留，不得静默覆盖。

### 2. 心超报告

`rdr_exam_master_report` 的心超相关项目包括普通心脏彩超/TTE、【床旁专用】超声心动图、床旁超声心动图、经食道超声/TEE、心脏疾病心超专科化评估等；报告同时有“检查结论”和“检查所见”。样例报告可以看到 EF、房室大小、室壁运动、瓣膜反流、肺动脉压、组织多普勒等结果。

这支持院内严格队列的三层心超判定：

`echo_performed` -> `echo_result_available` -> `echo_abnormal_support`

但“检查名称”或“床旁心超已做”不能直接代表异常；报告明确正常、结果缺失、无法解析和异常必须分开编码。HFpEF 不能因 LVEF 保留而排除，需保留舒张功能/充盈压、左房、左室肥厚、右心、肺动脉压和瓣膜等信息。

### 3. 床旁记录和临床表型

`rdr_bedside` 含 HR、血压、MAP、SpO2、呼吸、体温、尿量、出入量、给氧方式、呼吸音、水肿、毛细血管充盈等项目，可支持部分生命体征、液体管理、呼吸支持和 DHF 临床证据抽取。病程、入院记录、会诊记录、护理记录可用于提取呼吸困难、端坐呼吸、湿啰音、外周水肿、肺水肿和替代诊断等概念。

### 4. 用药与 ICU 结局的边界

病程和护理文本可以发现“使用/停用去甲肾上腺素”等叙述，但这不等同于实际 eMAR：无法仅凭文本稳定重建每段开始、停止、速率、浓度、剂量和实际执行状态。因此，文本用药只能作为治疗强化/可行性审计，不能直接用于 NEE、连续 30 分钟支持升级或 overt shock proxy。

同理，出 ICU 文书可支持部分“转病房/转出”情形，但样例未证实存在独立且完整的 ICU 出科生命状态和 ICU 内死亡时间字段。死亡记录、抢救记录、出科状态及后续 ICU stay 必须单独抽取并人工验证。

## 仍需向信息科确认

1. 是否有结构化 ICU stay 表，能以 `就诊号` 稳定连接 `intime/outtime`、ICU 类型、转入来源、转出去向、再入 ICU 序号和出科生命状态。
2. 若无结构化 ICU 时间，是否允许使用入/出 ICU 文书正文的明确时间；正文时间是否有记录者时间、事件时间和修订状态。
3. “检查[报告]日期”是检查完成、报告形成、归档还是结果可见时间；能否提供检查完成、报告可见、签署、修订/作废时间。
4. 心超是否能区分 TTE、TEE、POCUS/床旁心超和专科化评估；是否能提供完整所见、结论、结构化参数和报告状态。
5. 是否存在真实 eMAR/执行表，能否重建血管活性药、正性肌力药、IV 袢利尿剂的时间、速率、剂量、单位和执行状态。
6. 是否存在 ICU 内死亡时间、住院死亡时间、抢救记录、出科生命状态、机械循环支持和 CRRT 时间。
7. 床旁、检验和药物项目代码、单位、缺失原因及系统迁移日期。

## 推荐的院内核对方法

你的做法可行：分析端先输出候选时间和来源，随后你在院内病历系统用同一患者 token/就诊号定位原始界面，核对后回填结果。建议不要只回填“对/不对”，而使用以下字段：

| 字段 | 填写内容 |
|---|---|
| `candidate_time` | 数据抽取得到的候选时间 |
| `candidate_source` | 结构化字段、医嘱、病程、护理记录或报告字段 |
| `verified_flag` | 0/1/不确定 |
| `verified_time` | 院内系统核对后的实际时间 |
| `verified_source` | ICU 流转界面、eMAR/输液泵、医嘱、报告、病程等 |
| `discrepancy_reason` | 开立与执行不同、补录、停嘱不等于停药、报告延迟等 |
| `reviewer/date` | 核对者与核对日期 |

具体判断：

- ICU：优先核对结构化 `intime/outtime`；没有时再核对入/出 ICU 文书正文时间。
- 心超：核对实际检查时间、报告形成/可见时间，以及所见/结论是否支持结构或功能异常。
- 检验：使用采样时间作为事件时间，结果时间作为可用时间；不要用“开具时间”替代采样时间。
- 药物：医嘱开具/停止时间先作为候选计划时间；只有 eMAR、输液泵或经病程/护理记录核对的实际执行证据，才可作为实际开始/停止。速率同理。
- ICU 死亡/出科：核对出科状态、死亡时间和转科去向，不能用“出 ICU 文书存在”直接推定存活。

推荐先抽取 20-50 例，覆盖正常、一致、不一致、补录、停嘱和连续泵注等场景；通过后再全量提取。你不需要向我提供姓名或原始病历全文，只需返回去标识化 token、候选值、核对结果和必要的最小证据类别。
