# 任务报告：任务报告机制与文件整理

日期：2026-09-17

## 1. 用户问题与本轮范围

用户建议每次提问或回复生成任务报告，以便后续对话恢复上下文，并同步更新现有任务总览或研究进展；随后确认采用该方案并要求整理文件夹。

## 2. 已确认方案

采用“重要回合单独报告”的 A 方案：凡涉及研究结论、方法决策、数据处理、文件修改或阶段交付，生成一份独立任务报告；不改变研究状态的简单确认不单独建档，可并入最近报告。

任务报告采用追加式历史记录，不覆盖旧报告。若结论发生变化，后续报告必须写明旧结论、新结论和修正原因。

## 3. 文件组织

已建立：

```text
/workspace/inbox/task_reports/
├── README.md
├── TASK_REPORT_20260917_VARIABLE_SELECTION_PROMPT_AUDIT.md
└── TASK_REPORT_20260917_REPORTING_WORKFLOW.md
```

现有研究总览和方法文件继续保留在 `/workspace/inbox/` 根目录，避免破坏已有路径；新增任务报告集中放入 `task_reports/`。

## 4. 固定报告内容

每份报告包含：

1. 用户问题与本轮范围；
2. 文件、版本和数据状态；
3. 已验证事实与证据；
4. 判断与影响；
5. 新增或确认的研究决策；
6. 未决问题、阻塞项和假设；
7. 下一步动作；
8. 本轮修改文件；
9. 适用时的脚本、版本、seed、折索引和输入指纹。

## 5. 总览维护规则

`RESEARCH_DASHBOARD.md` 只维护当前研究状态，不重复全部过程。每次实质更新时同步：

- 更新日期；
- 当前阶段和一句话状态；
- 新增或修正的研究决策；
- 当前阻塞项和下一步；
- 任务报告索引；
- 更新日志。
