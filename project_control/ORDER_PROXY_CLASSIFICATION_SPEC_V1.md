# 医嘱治疗升级代理分类规范 v1

版本：2026-09-16。用途：在eMAR暂不可得时，把未作废医嘱、时间区间、给药途径和文书支持转成可审计的治疗暴露代理。该规范不把医嘱等同于实际给药，也不把文书共现当作独立金标准。

## 1. 适用范围

仅处理预先登记的目标治疗组（血管活性药、正性肌力药、机械循环支持或其他明确写入结局合同的升级治疗）。药物名称、浓度、剂量和途径必须先经过变量字典映射；无法映射的医嘱进入`unknown_order_class`，不得凭药名相似性归类。

## 2. 时间定义

- `T0`：确认的index ICU入区时间；`T12=T0+12h`。
- 只用医嘱开立/开始、停止/废止及途径字段建立代理窗口。创建日期不能替代开始时间。
- 区间与`[T0,T12)`相交时记录相交部分；跨T0的医嘱单独保留`preT0_continuation_uncertain=1`。
- 同一药物的重复医嘱保留原行并建立order-level唯一键；只有完全相同的来源、时间和标识才允许去重。

## 3. 分类规则

| class | 判定 | 允许的解释 |
|---|---|---|
| `IV_infusion_started_pre12` | 途径明确为泵入/持续输注，开始时间在`[T0,T12)`内，且未在开始前废止 | 窗口内有持续治疗医嘱代理；不是给药确认 |
| `IV_infusion_interval_overlaps_pre12` | 泵入/持续输注区间与`[T0,T12)`相交，但开始时间早于T0或停止时间晚于T12 | 有区间重叠；跨T0部分的实际持续性仍不确定 |
| `IV_point_order_pre12` | 途径为普通静脉注射/静脉推注，且开立或执行计划时间落在窗口内，不能证明连续泵入 | 单次点用代理；不得转换成持续输注或泵速 |
| `preT0_order_continuation_uncertain` | 医嘱在T0前开始、窗口内仍有效，但缺少可靠执行/停止证据 | 只能作为不确定代理或敏感性分支 |
| `text_supported_without_order` | 窗口内文书明确记录已给予/正在泵入，但没有可匹配的有效医嘱 | 文书支持的下界；不能反向补造医嘱时间 |
| `planned_only_possible_proxy_mismatch` | 文书只有“计划/准备/必要时”而无已给予证据，或医嘱与文本时间明显错位 | 记为计划或错位，不计入确认治疗事件 |
| `no_signal` | 无目标医嘱且文书无目标治疗提及 | 阴性对照，不证明从未接受院外/未提取治疗 |
| `unknown_order_class` | 药物、途径或时间无法按字典解析 | 保留原文和原因，进入缺失/敏感性审计 |

同一episode可同时存在多个类别；事件构建时按结局合同规定的优先级聚合，不能以最后一条医嘱覆盖前面类别。

## 4. 文书核对规则

文书用于支持、反驳或解释时间错位，优先级为：抢救/护理执行记录和明确“已给予/正在泵入”描述，高于计划性描述；SOAP转出计划只能用于确认转归或观察链，不单独证明治疗已经执行。文书核对必须保存文件、行号、原文片段、时间和判读状态。

## 5. 50例审计的正确解释

`order_proxy_text_validation_50.csv`为分层可行性审计，不是eMAR验证。当前50例包括13例泵入开始、10例区间重叠、10例单次点用、5例延续不确定、7例无医嘱但有文本、5例双阴性。文字共现只能提供支持下界；在没有独立执行记录时，不计算敏感度、特异度、PPV或NPV，也不解除正式结局冻结门控。

## 6. 结局使用限制

医嘱代理可用于预设的“治疗升级相关”组成部分，但必须在结果中标注`order_proxy`来源和不确定性。不得从总剂量反推泵速、持续时间或NEE；不得把医嘱开立时间写成给药开始时间。eMAR或护理执行记录取得后，使用同一队列、同一时间轴和同一聚合规则进行敏感性重跑，并比较事件组成、方向和校准变化。

## 7. 版本控制

本规范变更需新增版本号，并在`run_registry.csv`记录脚本、字典、输入快照、差异原因和输出哈希。正式结局冻结前，所有依赖本规范的数字均标记为`working`或`audit`。
